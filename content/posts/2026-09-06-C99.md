整理一下C99里面我不知道的一些东西，原本以为我"学过C了"，结果一看实际的代码发现太多我不懂的了...

标准是ISO/IEC 9899:1999，gcc里用`-std=c99`打开（`-std=gnu99`会额外带上GNU扩展），想知道编译器按哪版标准编，看`__STDC_VERSION__`。

## 关于宏

宏就是给预处理器 / 编译器处理的，因此行为也会和编译器有关

1. **可变参数宏：**
```c
#define Log(format, ...) printf(format, __VA_ARGS__)
```
C99开始就引入了可变参数宏，这里我们使用时就可以写:
```c
Log("%d", x);
```
`...`对应宏体里的`__VA_ARGS__`。有个坑是一个参数都不传的时候（`Log("hello")`）会展开成`printf("hello", )`这种语法错误，所以GNU的写法是在前面加一个`##`：
```c
#define Log(format, ...) printf(format, ## __VA_ARGS__)
```
这是GNU扩展，不是C99本身，C23才给了标准的`__VA_OPT__`。另外`#`和`##`本身是C89就有的，不算新东西

2. **预定义宏：**

| 宏/标识符                  | 描述                                                                   | 谁替换/提供 |
| -------------------------- | ---------------------------------------------------------------------- | ----------- |
| `__DATE__`                 | 编译日期，字符串字面量，形如 `"Sep  6 2026"`（`dd` 不足 10 时前面补空格） | 预处理器    |
| `__LINE__`                 | 当前源代码行号，整数常量（可被 `#line` 改变）                          | 预处理器    |
| `__FILE__`                 | 当前源文件名，字符串字面量（可被 `#line` 改变）                        | 预处理器    |
| `__TIME__`                 | 编译时间，字符串字面量，形如 `"23:59:01"`                              | 预处理器    |
| `__STDC__`                 | 展开为整数常量 `1`，表示实现符合 ISO C                                 | 预处理器    |
| `__STDC_VERSION__`         | 实现支持的 C 标准版本号（`long` 类型）；C99 为 `199901L`               | 预处理器    |
| `__STDC_HOSTED__`          | 宿主环境为 `1`，独立（freestanding）环境为 `0`                         | 预处理器    |
| `__STDC_IEC_559__`         | 若支持 IEC 60559 浮点运算，定义为 `1`（可选）                          | 预处理器    |
| `__STDC_IEC_559_COMPLEX__` | 若支持 IEC 60559 复数运算，定义为 `1`（可选）                          | 预处理器    |
| `__STDC_ISO_10646__`       | 若 `wchar_t` 使用 Unicode，展开为形如 `yyyymmL` 的整数常量（表示所支持的 Unicode 版本），否则未定义（可选） | 预处理器    |
| `__STDC_MB_MIGHT_NEQ_WC__` | 若基本字符集里可能出现 `'x' != L'x'`（如 EBCDIC 系统），定义为 `1`（可选） | 预处理器    |
| `__func__`                 | 当前函数名，C99 引入的函数局部预定义标识符（不是宏）                   | 编译器      |
| `__OBJC__`                 | Objective-C 编译器扩展宏，使用 Objective-C 时通常定义                  | 编译器扩展  |
| `__cplusplus`              | C++ 编译器扩展宏；使用 C++ 时定义，值表示语言版本                      | 编译器扩展  |

这些很有用！就比如说我们可以结合`__LINE__`和`__FILE__`来进行错误处理和反馈：（这是NEMU里面的)
```c
#define Log(format, ...) \
    _Log(ANSI_FMT("[%s:%d %s] " format, ANSI_FG_BLUE) "\n", \
        __FILE__, __LINE__, __func__, ## __VA_ARGS__)
```
这里`"[%s:%d %s] " format`是相邻字符串字面量的拼接，编译期就把日志前缀和调用方传进来的format接在一起了；`## __VA_ARGS__`还是前面那个GNU扩展

[GNU专门的预定义宏](https://gcc.gnu.org/onlinedocs/cpp/Common-Predefined-Macros.html)

甚至还有特定系统对应的宏，就比如说 ISA / kernel 相关的信息，我们只需要检查对应的宏有没有定义就好了！常碰到的有`__x86_64__`、`__riscv`、`__linux__`、`__GNUC__`这几个

3. **新增的类型**

- `_Bool`：真的布尔类型（1字节），配`<stdbool.h>`就有`bool` / `true` / `false`
- `long long`：至少64位，printf用`%lld` / `%llu`
- `<stdint.h>`：`int8_t`到`uint64_t`、`intptr_t`这些确定位宽的类型和极值
- `<inttypes.h>`：可移植的格式串，`PRId64` / `PRIu32`这种
- `_Complex` / `_Imaginary`、`<fenv.h>`

`long`在64位Linux上是64位、在Windows上是32位，所以"我要64位整数"应该写`long long`或者`int64_t`

4. **语法上新加的**

- 声明可以混在语句里，`for (int i = 0; ...)`也是C99才允许的，C89得把i提前声明
- 指定初始化器，写寄存器表、协议字段很好用：
```c
struct point p = { .y = 2, .x = 1 };
int a[100] = { [10] = 1, [20] = 2 };
```
- 复合字面量，临时造一个匿名的结构体或者数组，还能直接取地址：`draw(&(struct rect){ .w = 10, .h = 20 });`
- 柔性数组成员，最后一个成员写`[]`，长度分配的时候再定：
```c
struct str { size_t len; char data[]; };
```
- 变长数组VLA，C99引入但C11变成了可选，不少嵌入式编译器不支持，而且它在栈上，n大了直接爆栈，我现在还是用malloc
- `va_copy`，复制一份`va_list`，两个可以各自独立遍历
- 零碎的还有：`restrict`、`inline`（`static inline`放头文件里是我现在最常用的写法）、`snprintf`、十六进制浮点字面量`0x1.8p3`、`void f(int a[static 10])`、能在宏里用的`_Pragma`、`//`注释、`LL`/`ULL`后缀和`%zu`
- 取消了隐式int：函数不声明就调用、不写返回类型默认int，在C99里都是违规的，搬老代码过来经常卡在这一条上
