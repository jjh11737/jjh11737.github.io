> 学习时碰到链接脚本，因此准备了解一下这玩意如何工作的
>
> 自然是RTFM，我看的是[官方文档](https://ftp.gnu.org/old-gnu/Manuals/ld-2.9.1/html_chapter/ld_1.html)

`ld`是一个链接工具，把各种目标和archive文件结合起来做重定位和符号解析，形成可执行文件。一般我们编译程序最后一步就是用`ld`。它接收的是`Linker Command Language`文件，

`BFD(Binary File Descriptor)`库，它定义了一套接口和例程用来统一处理各种目标文件（无论是何种格式），而真正的细节被后端藏了起来，而`ld`本身则只需要关注canonical form就可以工作

## 它具体干了两件事

1. 符号解析：把每个目标文件里"用到了但没定义"的符号和别处"定义了"的符号对上。对不上就是`undefined reference to ...`，对上了两处就是`multiple definition of ...`
2. 重定位：目标文件里的地址都是从自己开头算的（`.o`里那些`R_RISCV_CALL`之类的重定位项），`ld`决定每个section最终落在哪个地址，再把所有引用改写成最终地址

输入是`.o`、静态库`.a`（按需抽取成员）、共享库`.so`，输出可以是可执行文件、共享库，或者又一个`.o`（`-r`）。平时我们不直接调`ld`，是`gcc`在最后一步替你调（`gcc -v`能看到那一长串），所以给`gcc`传链接器参数要加`-Wl,`：

```bash
ld -o a.out crt0.o main.o -T my.ld -Map a.map
gcc -Wl,-T,my.ld -Wl,-Map=a.map -o a.out crt0.o main.o
```

## 脚本长什么样

`abstract-machine`的`scripts/linker.ld`是个很好的小例子：

```ld
ENTRY(_start)
PHDRS { text PT_LOAD; data PT_LOAD; }

SECTIONS {
  /* _pmem_start和_entry_offset是LDFLAGS里定义的 */
  . = _pmem_start + _entry_offset;
  .text : {
    *(entry)
    *(.text*)
  } : text
  etext = .;
  _etext = .;
  .rodata : { *(.rodata*) }
  .data : { *(.data*) } : data
  .bss : {
    _bss_start = .;
    *(.bss*)
  }
  _stack_top = ALIGN(0x1000);
  . = _stack_top + 0x8000;
  _stack_pointer = .;
  end = .;
  _end = .;
  _heap_start = ALIGN(0x1000);
}
```

说明：

- `ENTRY(_start)`：入口符号，`ld`会把它写进ELF头的`e_entry`
- `SECTIONS`：把输入文件的section拼成输出的section，并决定它们放在哪
- `.`是location counter，也就是当前地址。`x = .;`是把当前地址记到一个符号里，`. = 0x80000000;`是"从这里开始往下排"
- `*(entry)` / `*(.text*)`是通配符匹配输入文件里的section。`*(entry)`表示所有目标文件里名叫`entry`的section，而每个ISA的`start.S`开头都有`.section entry, "ax"`，这样入口代码就一定排在最前面
- `ALIGN(0x1000)`是向上对齐
- `_etext = .;`这种不是C变量，是链接期写进符号表的一个地址常量。C里要用得声明成`extern char _etext[];`
- `KEEP(...)`：`--gc-sections`会把没人引用的section丢掉，`KEEP`强制保留（中断向量表、启动代码就靠它）
- `PROVIDE(x = .)`：只有在代码里没定义`x`的时候才由脚本提供
- `MEMORY`是声明内存区域（`rom (rx) : ORIGIN = 0x0, LENGTH = 256K`），section用`> rom`放进去，裸机和嵌入式里几乎必写
- `AT>`指定加载地址（比如躺在flash里），`>`指定运行地址，启动代码负责把数据从flash搬到RAM，脚本里那些`_data` / `edata` / `_bss_start`就是干这个用的

符号也可以从命令行塞进来，AM就是这么干的：
```bash
LDFLAGS += --defsym=_pmem_start=0x80000000 --defsym=_entry_offset=0x0
```
所以同一个`linker.ld`配上不同的`--defsym`，就能在NEMU / NPC / logisim之间切换起始地址

## 看不懂的脚本怎么读

```bash
ld --verbose | less 
readelf -S a.out           # 有哪些section、在什么地址
readelf -l a.out           # program header
readelf -s a.out           # 看符号表
objdump -d a.out | head    # 反汇编
ld -Map=a.map ...          # 生成map：每个section来自哪个.o、最终落在哪
```

## 其它常用选项

- `-T script.ld`：用指定脚本取代默认脚本，`-Ttext=0x80000000`是偷懒版，只改某个section的地址
- `--defsym=sym=value`：从命令行定义符号
- `-e symbol`：指定入口符号
- `-lfoo` / `-Lpath`：找静态库 / 共享库
- `--start-group ... --end-group`：静态库之间有循环依赖时让它们反复查找
- `-static` / `-shared` / `-pie`：不依赖动态库 / 共享库 / 位置无关可执行文件
- `--gc-sections`：回收没被引用的section
- `-z noexecstack`：标记栈不可执行，安全加固，gcc默认会加
