常用的方法

## 找

- `ps -ef | grep <名字>` / `ps aux`
- `pgrep -a <名字>`，`-f`匹配整条命令行，`-n`只要最近一个，用起来很方便：`strace -p $(pgrep -n nvim)`
- `pidof <名字>`
- `top` / `htop`，htop里F5看树、F6排序、K杀进程
- `pstree -p`看父子关系

## /proc

每个进程在`/proc/<pid>/`下都有一份自己的档案，命令行要的东西基本都在里面：

- `cmdline`：启动命令（`\0`分隔，`tr '\0' ' '`一下才好看）、`cwd`、`environ`
- `fd/`：打开的文件描述符
- `maps`：内存映射
- `status`：状态、线程数、上下文切换次数
- `stack` / `wchan`：内核侧调用栈 / 睡在哪个内核函数
- `syscall`：此刻正在执行哪个系统调用
- `limits`：各种资源上限

```bash
$ cat /proc/6095/status | head
$ ls -l /proc/6095/fd
$ cat /proc/6095/cmdline | tr '\0' ' '; echo
```

`ls -l /proc/<pid>/fd`是我用得最多的：一个进程卡住了，先看它开着哪些fd，基本就知道它在等什么。

## 卡住

```bash
cat /proc/<pid>/wchan             # 睡在哪个内核函数
sudo cat /proc/<pid>/stack        # 内核调用栈，要root
sudo cat /proc/<pid>/syscall      # 此刻在跑哪个syscall
strace -p <pid> -f                # 跟它发的系统调用，-f连子进程/线程
ltrace -p <pid>                   # 库函数层面
gdb -p <pid> -batch -ex bt        # 会把它停住，记得detach
```

`strace -p`输出里那个没写完的调用（比如`read(5,`）就是它卡住的地方，再拿`/proc/<pid>/fd`把那个fd翻译回文件或者socket。

我一般是按这个顺序走的：`pgrep -n`拿pid → `ps -o pid,ppid,stat,wchan,cmd -p <pid>`看状态 → `cat /proc/<pid>/stack` → `strace -p <pid> -f` → `ls -l /proc/<pid>/fd`

## 占用

- `ss -tunap | grep <pid>`：这个进程的socket
- `lsof -p <pid>` / `lsof -i :8080`
- `fuser -vm /mnt/data1`：谁占着挂载点，卸载失败的时候用

## 资源

- `nice -n 10 <cmd>` / `renice -n 5 -p <pid>`
- `ionice -c3 -p <pid>`
- `taskset -c 0,1 <cmd>`
- `ps -T -p <pid>` / `top -H -p <pid>`看线程
- `systemctl status <unit>` / `systemd-cgls`，服务类的进程从systemd的角度看

## 信号

```bash
kill -TERM <pid>                  # 默认，请求它体面退出
kill -9 <pid>                     # 内核直接干掉，没机会善后，最后手段
kill -STOP <pid> / -CONT <pid>    # 暂停 / 继续
kill -l                           # 所有信号名
```

`Ctrl-Z`挂起（等于SIGTSTP），`jobs` / `fg` / `bg`管回来；`nohup`、`disown`、`setsid`是让它别跟着终端死。要断开ssh也不死，我还是用tmux。
