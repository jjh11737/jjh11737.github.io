# crackmes!(0)

之前上网看到了一个很有趣的网站：[crackmes](https://crackmes.one/)，刚好我之前做bomb lab后觉得有些没法满足，那为什么不试试看？

这个函数叫`vulnerable_function`，那么它到底为什么`vulnerable`？首先栈帧开了80字节的大小，那么我们看看函数调用，这里让我比较感兴趣的是这个`read`的调用，它传入了3个参数：0,a5,256，我们知道：
```c
概述
       #include <unistd.h>

       ssize_t read(int fd, void *buf, size_t count);
```
而看前面的代码，`a5=s0-80`，而`s0=sp+80`...换句话说，我们的缓冲区在栈上...而且最糟糕的是它正好在栈底部
那么一个很自然的想法，这个缓冲区既然几乎必定溢出，我们完全可以利用这一点，修改返回地址刚好跳转到我想要的地方！因为很显然前面已经知道了`ra`被放在`sp + 72`的地方了，那么我只要写的刚好覆盖这个地址就行了？

而看elf里面已经有了应该输出的字符串：

我觉得差不多了！想法大概就是我们构造一个输入的字符串，刚好覆盖到`ret`的地方，嗯，通过管道交给它就好了，可以用python干这件事：
```bash
python3 -c "import sys; sys.stdout.buffer.write(b'A'*72 + (0x0000000000010476).to_bytes(8, 'little'))" | qemu-riscv64 ./securevault
```
成功了！
