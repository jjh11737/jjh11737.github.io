## Machine modes

一般来说，我们的machine modes往往被分为2类：

- Priviledged Mode

  机器启动时的状态，此时任何指令和地址访问都是允许的

- Unpriviledged Mode

  当操作系统接管控制权并开始执行用户代码，模式就切换为这个状态了

但是这个区分太课本也太简单了，事实上一个系统往往有超过2个mode来形成一个[protectionRing](https://en.wikipedia.org/wiki/Protection_ring)

> 比如x86有4个Ring，Ring0可以做任何事，而Ring3只要试图对系统别的部分做什么都会失败
>
> 在多数系统中，从用户态切换到内核态往往意味着**较高的性能开销**。
>
> （wikipedia这里举了`getpid`的例子，说1000~1500个周期里面实际上只有100多个周期真正是花在switch上的，剩下的都是_"kernel overhead"_，也就是内核开销
>
> > 既然如此，为什么我们不自己测量一下呢？也就是我们完全可以通过库打桩来测量一次调用的时间！而且还可以用`perf`看一下

RISC-V不要求具体的Modes，但是你必须至少实现M-mode（基本上也只有简单的嵌入式裸机会这样），而U/S则是可选的

> H扩展是为硬件虚拟化提供支持的特权架构扩展，具体来说就是在每个Guest OS到机器之间又加了一层

术语：

1. 基本概念：

- SBI：Supervisor Binary Interface

  Supervisor软件(S-mode/VS-mode)和更高特权级别软件的标准接口，好处在于可以屏蔽不同平台的底层实现差异
  >作为硬件，实际上只需要关注Mechanism
  >
  >- 特权状态
  >- 访存检查
  >- 特权指令检查
  >- 受控的控制流切换
  >
  >而Policy才是操作系统要关心的

- SEE：Supervisor Execution Environment

  在Supervisor软件提供服务的一侧

  > 没有H扩展时，我们的OpenSBI就可以充当SEE

- EID：Extension ID

  SBI通过具体的扩展来提供相应的功能，那么这个ID就是说明我们要调用哪一组SBI服务。（放在`a7`寄存器里面）

- FID：Function ID

  函数标识符，用于指定扩展内部具体操作

2. 地址空间 / 虚拟机：

- VMID：Virtual Machine Identifier

  虚拟机标识符。用于区分虚拟机相关的地址转换上下文

- ASID：Address Space Identifier

  地址空间标识符，主要是用于区分不同的地址空间让地址转换硬件识别某个缓存的地址转换属于哪个地址空间。也就是地址转换上下文

3. hart相关：

- HSM：Hart State Management

  RISC-V使用_hart_(hardware thread)作为架构层面的执行单元概念。
  而这个扩展就是提供给S-mode来管理另一个hart的接口

- IPI：Inter Processor Interface

  处理器间通信机制

4. 性能监控：

- PMU：Performance Monitoring Unit

  性能监控单元，可以计数某些硬件的事件

  > （换句话说`perf`应该就是在调用这个？） 

5. 平台配置和性能管理：

- ACPI：Advanced Configuration and Power Interface

  高级配置与电源接口

- BMC：Baseboard Management Controller

  基板管理控制器

- CPPC：Collaborative Processor Performance Control

  协作式处理器性能控制

## 二进制接口

calling convention：

- `ECALL`被用于在SEE和supervisor之间传递控制权

- `a7`传递EID

- `a6`传递FID

- 除了`a0`/`a1`，其他的寄存器都需要被调用者保存

- SBI函数必须返回一对值在`a0`/`a1`，其中`a0`返回错误码，你可以理解为：
  ```c
  struct sbiret{
      long error;
      long value;
  };
  ```
